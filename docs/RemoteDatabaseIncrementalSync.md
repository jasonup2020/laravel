# 13个远程数据库数据每日增量同步可行性技术文档（优化版）

# 一、文档概述

## 1.1 项目背景

本地计划部署14张客户相关业务表，支持自动创建表结构（若本地表不存在）；存在13个远程数据库，各远程库表结构与本地目标结构完全一致，且所有远程库中对应表的主键ID存在重复问题。

需求为：支持13个远程数据库并发数据同步，每日自动从各远程库中拉取最新客户及关联数据，合并至本地数据库；核心要求为——各远程库同步至本地的数据关联正确，无ID冲突，支持并发连接优化、ID映射持久化（采用JSON/CSV存储）、外键关联自动转换，采用CSV记录同步进度，实现增量同步与断点续传；ID映射仅处理当前次执行的13个库新数据，历史映射数据单独备份归档。

## 1.2 核心目标

- 并发同步：支持13个远程数据库并发同步，提升同步效率，性能较传统模式提升6倍以上，确保同步过程不占用过多服务器资源。

- 数据完整性：13个远程库14张客户相关表的完整同步，支持本地表自动创建，每日新增数据完整同步至本地，无数据丢失、无重复同步。

- 关联一致性：自动处理外键关联，按依赖顺序同步表，将子表外键转换为本地ID，支持常规外键与特殊关联（如email关联），确保关联正确、无断裂。

- ID统一性：自动生成本地新ID，采用JSON/CSV存储远程ID与本地ID的映射关系并持久化，仅处理当前次13个库新数据映射，历史数据单独备份，支持多库数据合并，彻底避免ID冲突。

- 增量高效：使用CSV文件记录每个远程库每张表的最大ID，仅同步新增数据，避免重复，支持断点续传，同步中断后可快速恢复，不重复处理已同步数据。

- 连接可靠：自动测试远程库所有可用IP（db_host、server_ip、server_inner_ip），3秒超时检测，自动切换备用IP，完善异常处理机制，保障同步稳定性，规避关联网站异常对同步的潜在影响。

## 1.3 技术栈选型（优化版）

基于核心功能需求，选用以下技术栈保障方案落地，兼顾并发性能、可操作性与稳定性，针对现有问题优化适配，不改动表结构：

- 后端框架：Laravel 13（依托其命令行工具、数据库连接管理、定时任务、并发处理功能实现同步逻辑，优化任务调度机制，避免并发过载）。

- 数据库：MySQL（与远程库现有数据库类型一致，保障数据兼容性，支持自动建表，不改动本地与远程库表结构、字段属性）。

- 进度记录：CSV文件（替代原有Excel，适配JSON+CSV整体存储逻辑，用于记录各远程库每张表的最大ID，读写高效、格式简洁；优化文件读写机制，避免文件损坏、丢失，提升进度记录可靠性）。

- 任务调度：Laravel定时任务 + Linux Crontab（实现每日自动同步，支持手动触发，优化定时任务容错机制，避免任务重复执行、漏执行）。

- 并发处理：Laravel 并发任务（实现13个远程库同时同步，优化并发线程控制，根据服务器配置动态调整线程数，避免服务器过载）。

- CSV操作：PHP内置CSV函数（实现CSV文件的读写、编辑，记录同步进度，无需额外依赖，轻量高效；新增CSV文件校验机制，避免格式错乱、读写失败）。

- 映射存储：采用JSON文件作为运行时映射存储（处理当前13个库新数据映射），CSV文件作为历史数据备份归档，无需新增本地数据库映射表，实现无侵入式存储；同步进度也采用CSV存储，统一文件格式，便于管理；优化映射写入、备份机制，避免映射数据丢失、错乱。

### 3.3.1 JSON运行时存储（核心，处理当前新数据映射）

- 文件路径：storage/app/mappings/id_mapping.json

- 存储用途：运行时核心映射文件，仅维护当前及历史所有有效映射关系（每次同步仅新增当前13个库的新数据映射，不删除历史有效映射），供同步过程中快速查询、替换外键使用。

- 结构设计：三层嵌套结构，查询效率达O(1)，贴合多库多表映射需求，格式如下：`{
  "savebullets_com": {
    "oc_customer": {
      "1": 1001,
      "2": 1005
    },
    "oc_address": {
      "5": 2001
    }
  },
  "naomifinds": {
    "oc_customer": {
      "1": 2001,
      "2": 2002
    }
  }
}`

- 结构说明：第一层Key为远程库名（如savebullets_com），第二层Key为表名（如oc_customer），第三层Key为远程ID，Value为本地ID，确保“远程库+表+远程ID”唯一对应本地ID。

- 优化点：新增JSON文件实时校验机制，同步过程中每10分钟校验一次文件完整性，避免文件损坏；新增映射去重逻辑，防止重复写入映射数据，确保映射关系唯一。

### 3.3.2 CSV历史备份存储（归档，不参与运行时）

- 文件路径：storage/app/mappings/history/

- 存储用途：仅用于历史映射数据备份归档，不参与同步过程中的映射查询与处理，每次同步完成后自动备份当前批次新映射数据，便于追溯、回滚。

- 命名规则：按同步时间命名，格式为history_YYYYMMDD_HHMMSS.csv（如history_20260410_120000.csv），每个文件对应一次13个库的同步批次，仅存储本次批次的新数据映射。

- 格式设计：表头为“db_name,table_name,remote_id,local_id,timestamp”，每行对应一条新映射记录，示例如下：
        `db_name,table_name,remote_id,local_id,timestamp
savebullets_com,oc_customer,1,1001,2026-04-10 12:00:00
savebullets_com,oc_address,5,2001,2026-04-10 12:00:00
naomifinds,oc_customer,1,2001,2026-04-10 12:00:01`

- 优化点：新增CSV备份文件校验机制，备份完成后自动校验文件格式和数据完整性，校验失败则重新备份；优化备份存储策略，备份文件保留7天，自动清理过期备份，节省存储空间。

### 3.3.3 CSV同步进度记录（核心，替代Excel）

- 文件路径：storage/app/mappings/sync_last_max_ids.csv

- 存储用途：替代原有Excel，用于记录每个远程库每张表的最大同步ID，作为增量同步、断点续传的核心依据，读写高效、格式简洁，与映射备份CSV统一格式，便于管理。

- 格式设计：表头为“db_name,table_name,max_id,sync_time”，每行对应一个远程库、一张表的同步进度，示例如下：
        `db_name,table_name,max_id,sync_time
savebullets_com,oc_customer,100,2026-04-10 12:00:00
savebullets_com,oc_address,50,2026-04-10 12:05:00
naomifinds,oc_customer,80,2026-04-10 12:00:01`

- 补充说明：同步进度CSV与映射备份CSV分开存储，用途区分明确；进度CSV实时更新，每次单张表同步完成后立即写入，确保进度记录准确，支持手动编辑调整，适配增量同步与断点续传需求。

- 优化点：新增进度文件双重备份机制，主文件与备份文件实时同步，主文件损坏时自动切换至备份文件，避免进度丢失；新增进度数据校验逻辑，防止手动编辑或写入错误导致的进度错乱。

整体说明：JSON文件用于运行时快速查询，确保同步效率；CSV文件分为两类（历史映射备份、同步进度记录），分别实现历史归档与进度管理，仅处理当前新映射、单独备份历史数据，实现“当前处理+历史归档+进度记录”的统一管理，兼顾效率与可追溯性；所有优化均不涉及表结构改动，仅提升映射与进度管理的可靠性。

# 四、核心技术方案（贴合核心功能，优化版）

## 4.1 核心设计思路（优化版）

以“并发同步、智能IP选择、JSON/CSV映射存储（当前新数据处理+历史备份）、CSV进度记录、外键自动转换”为核心，针对连接稳定性、数据一致性、异常处理等问题优化，不改动本地与远程库表结构，实现高效、稳定、可靠的多库同步，核心思路如下：

1. 多库并发同步：采用Laravel并发任务机制，同时启动13个远程库的同步进程，实现并发数据同步，相较于单线程同步，性能提升6倍以上；优化并发线程控制，根据服务器CPU、内存占用动态调整线程数，避免服务器过载。

2. 高可用连接：保留每个远程库的server_ip和server_inner_ip两个配置，同步时优先使用db_host建立连接；若db_host连接失败（3秒无响应），立即用server_inner_ip替换重试，每个IP连接超时时间严格控制在3秒，单个数据库单次最大超时时间支持配置，每个IP最多重试3次，确保连接稳定性；新增IP预检测机制，同步前提前验证所有可用IP连通性，提升连接效率。

3. ID映射机制：同步每条远程记录时，自动生成本地新ID，仅处理当前次13个库的新数据映射，新增映射关系写入内存，同步完成后批量更新至JSON运行时文件；同时将本次新映射数据单独备份至CSV文件，实现历史数据归档；多库合并时，通过JSON文件区分不同远程库的ID，避免冲突，确保本地ID统一性；优化映射写入机制，采用“先写入临时文件、再覆盖原文件”的方式，避免JSON文件损坏。

4. 外键关联处理：严格按照表依赖顺序同步（先主表、后子表），同步子表时，自动查询JSON运行时文件，将子表中的远程外键ID转换为本地ID；支持常规外键（如customer_id）和特殊关联（如email关联），确保关联关系正确；新增外键转换校验逻辑，转换后验证关联关系，避免关联错乱。

5. 增量同步与CSV进度记录：通过CSV文件记录每个远程库每张表的最大ID，每次同步仅查询远程库中“主键ID > CSV记录最大ID”的新增数据，避免重复同步；同步中断后，可通过CSV记录的最大ID实现断点续传；优化增量查询逻辑，减少远程库查询压力，提升同步效率。

6. 自动建表：同步启动前，检测本地14张客户相关表是否存在，若不存在，自动根据远程库表结构创建本地表，严格沿用远程库表结构、字段类型，不做任何修改，确保同步正常进行。

## 4.2 关键功能实现方案（优化版）

### 4.2.1 多库数据同步实现（优化版）

1. 自动建表：同步任务启动后，首先遍历14张客户相关表，查询本地是否存在对应表；若不存在，读取远程库对应表的结构，自动在本地创建表（保留字段类型、约束等核心信息，不新增、不修改任何字段）；新增建表校验机制，建表完成后对比本地表与远程库表结构，确保一致。

2. 并发调度：通过Laravel的ParallelTesting或任务队列机制，创建13个并发任务，每个任务对应一个远程库，实现13个远程库同时同步，互不干扰；优化任务调度机制，新增任务优先级设置，避免任务拥堵，确保同步高效推进。

3. 全表同步：每个远程库的同步任务中，按表依赖顺序，完成14张客户相关表的完整同步，确保数据不缺失、关联不中断；优化同步数据校验逻辑，同步完成后对比远程库与本地库数据量，确保数据完整。

### 4.2.2 并发连接优化实现（优化版）

1. 并发IP测试：同步每个远程库前，获取该库的db_host、server_ip、server_inner_ip三个IP，采用并发连接测试模式，同时向三个IP发起连接请求，提高IP命中效率，哪个IP先响应则优先尝试建立正式连接；优化IP测试逻辑，记录IP响应时间和连接成功率，后续同步优先选择连接稳定的IP。

2. 最优连接选择：记录所有响应IP的响应时间，最终选择响应时间最短的IP作为当前同步的连接IP，进一步提升同步效率；新增IP连接状态监控，同步过程中实时监控IP连接状态，出现异常立即切换。

3. 高可用重试与切换：连接过程中，若当前IP出现3秒无响应，立即切换至下一个IP重试；单个数据库单次最大超时时间可灵活配置，每个IP最多重试3次，3次均失败则切换至下一个可用IP，直至所有IP尝试完毕，确保同步不中断，同时记录IP异常日志，便于后续排查；针对关联网站异常的两个远程库，强化IP连接监控，避免网站异常影响数据库连接。

4. 性能提升：通过并发IP测试、最优连接选择及高可用切换机制，减少连接等待时间，同步性能较传统单线程、固定IP同步提升6倍以上；优化数据库连接池配置，减少连接建立、释放的耗时，进一步提升同步效率。

### 4.2.3 ID映射机制实现（JSON+CSV，当前处理+历史备份，优化版）

1. 本地ID生成：同步远程单条记录时，不使用远程ID，由本地系统自动生成唯一自增ID（确保所有远程库同步至本地的ID不重复）；优化本地ID生成机制，确保ID生成连续、唯一，避免ID断层。

2. 当前新数据映射处理：仅处理本次同步13个库的新数据映射，流程如下：
        

    - 同步启动时，读取id_mapping.json文件至内存，初始化空的临时映射数组（用于存储本次新映射）；若JSON文件不存在，初始化空数组；新增JSON文件校验，若文件损坏，自动基于最近一次CSV备份恢复。

    - 对于每条新拉取的远程记录（远程ID为A），先在内存的JSON映射数组中查询“当前库名+当前表名+A”是否存在，若不存在则生成本地ID（B），并将“库名-表名-A-B”的映射关系存入临时映射数组；新增映射去重逻辑，避免重复写入。

    - 本次13个库所有新数据同步完成后，将临时映射数组中的新映射批量合并至内存中的JSON映射数组，再一次性覆盖写入id_mapping.json文件，完成当前新映射的持久化；采用“先写入临时文件、再覆盖原文件”的方式，避免文件损坏。

3. 历史数据备份：本次同步完成后，将临时映射数组中的所有新映射数据，按CSV格式整理，以“history_YYYYMMDD_HHMMSS.csv”命名，保存至指定备份目录，实现历史数据单独归档，不影响JSON运行时文件；新增备份校验，备份完成后验证数据完整性，校验失败则重新备份。

4. ID冲突避免：多库数据合并时，通过JSON文件中“远程库名+远程表名+远程ID”的组合唯一标识每条远程记录，确保不同远程库的相同远程ID，同步至本地后对应不同的本地ID，避免冲突；新增ID冲突检测机制，同步过程中实时检测，发现冲突立即记录并告警。

5. 映射查询：同步关联表、特殊关联（如email关联）时，通过内存中的JSON映射数组快速查询远程ID对应的本地ID，查询效率极高，确保关联准确；优化映射查询缓存机制，提升查询效率。

### 4.2.4 外键关联处理实现（优化版）

1. 表依赖排序：提前定义14张表的依赖顺序（如：oc_customer_group → oc_customer → oc_address → 其他关联表），同步时严格按该顺序执行，确保主表数据先同步，子表可正常关联；固化表依赖顺序，不允许乱序同步，避免关联错乱。

2. 常规外键转换：同步子表（如oc_address）时，子表中的customer_id为远程ID，通过查询内存中的JSON映射数组，根据“远程库名+oc_customer+远程customer_id”找到对应的本地customer_id，将子表中的远程外键替换为本地ID，完成关联绑定；新增外键转换校验，转换后查询本地主表，确认关联存在，避免关联断裂。

3. 特殊关联处理：对于email关联等特殊场景，同步时通过“远程库名+email”唯一标识用户，查询本地对应的用户本地ID，完成关联绑定，确保特殊关联场景下的数据一致性；优化特殊关联查询逻辑，提升查询准确性和效率。

### 4.2.5 增量同步实现（CSV进度记录，替代Excel，优化版）

1. CSV文件存储：文件路径为本地服务器Laravel项目的storage/app/mappings目录下，文件名为sync_last_max_ids.csv，用于记录每个远程库每张表的最大同步ID，替代原有Excel，与映射备份CSV统一格式；优化文件存储权限，避免误删除、误修改。

2. CSV格式设计：表头为“db_name,table_name,max_id,sync_time”，每行对应一个远程库、一张表的同步进度，格式简洁、读写高效，便于查看和手动编辑；新增格式校验，确保文件格式统一，避免读写失败。

3. 增量判断：同步启动时，读取CSV文件中对应远程库、对应表的最大ID，仅查询远程库中“主键ID > 该最大ID”的新增数据，实现增量同步；若CSV文件不存在，自动创建并初始化表头，将所有远程库每张表的最大ID初始化为0，适配首次全量同步；优化增量查询逻辑，采用索引查询，减少远程库查询压力。

4. 断点续传：若同步任务中途中断（如服务器重启、程序崩溃），下次启动时，通过CSV记录的最大ID，从断点处继续同步，无需重新同步已完成的数据；JSON文件中的映射关系已持久化，无需重新生成，仅需继续处理未完成的新数据映射；新增断点记录机制，详细记录中断位置，便于快速恢复。

5. 进度更新：单张表同步完成后，立即更新CSV文件中对应记录的最大ID和同步时间，采用PHP内置CSV函数实现高效写入，确保进度记录实时准确，避免数据错乱；新增进度更新校验，更新后验证数据正确性，避免写入错误。

# 五、同步流程设计（优化版）

## 5.1 整体同步流程（每日自动执行，优化版）

1. 启动同步任务：通过Laravel定时任务，每日固定时间（如凌晨1:00）自动启动同步任务；也可手动触发同步；优化任务启动机制，新增任务锁，避免任务重复执行。

2. 自动建表检测：遍历14张客户相关表，检测本地是否存在，若不存在，自动根据远程库表结构创建本地表（严格沿用远程库结构）；检测JSON文件、CSV进度记录文件、CSV历史备份目录是否存在，不存在则自动创建；新增建表后结构校验，确保本地表与远程库表结构一致。

3. 读取CSV进度：读取sync_last_max_ids.csv文件，获取13个远程库每张表的最大ID和同步时间，存储至内存；若CSV文件不存在，初始化空进度数据（所有表最大ID为0）；若CSV文件损坏，自动切换至备份文件，若备份文件也损坏，基于JSON文件恢复进度。

4. 加载JSON映射：读取id_mapping.json文件至内存，初始化临时映射数组（用于存储本次新映射）；若JSON文件不存在，初始化空的JSON数组；若JSON文件损坏，自动基于最近一次CSV历史备份文件恢复映射数据。

5. 并发同步远程库：通过Laravel并发任务机制，同时启动13个远程库的同步任务，每个任务独立执行，互不干扰；优化并发任务监控，实时监控任务执行状态，出现异常及时记录并告警。

6. 单库同步闭环（核心步骤，优化版）：
         

    1. 高可用IP测试与选择：获取当前远程库的db_host、server_ip、server_inner_ip三个IP，保留server_ip和server_inner_ip配置；采用并发连接测试模式，同时向三个IP发起连接请求，3秒无响应立即切换下一个IP，优先使用db_host连接，db_host失败则用server_inner_ip替换重试，每个IP最多重试3次，单个数据库单次最大超时时间可配置；最终选择响应时间最短的IP建立连接，确保连接高效、稳定；针对关联网站异常的两个远程库，额外记录IP连接状态，便于后续排查。

    2. 同步基础表：按表依赖顺序，同步该远程库的基础表（如oc_customer_group），采用单条记录逐一处理模式：
                      

        - 查询该远程库基础表中“主键ID > CSV记录最大ID”的单条记录（远程ID为A）；优化查询逻辑，采用索引查询，提升查询效率。

        - 将该单条记录插入本地，生成本地新ID（B）；插入后校验数据完整性，确保插入成功。

        - 判断内存JSON映射数组中是否存在“当前库名+基础表名+A”的映射，若不存在，将该映射关系存入临时映射数组；新增映射去重校验。

        - 若该记录有关联数据（如oc_customer_group_description关联oc_customer_group），通过远程ID A查询关联数据，插入本地时，查询内存JSON映射数组获取本地ID B，用B替换远程ID A，完成关联绑定；关联后校验关联关系，确保正确。

        - 更新CSV中该远程库、该基础表的最大ID（取当前处理记录的远程ID A）和同步时间；更新后校验进度数据，确保准确。

        - 重复上述步骤，直至该基础表所有增量记录处理完毕。

    3. 同步用户主表（oc_customer）：采用单条记录逐一处理模式，每条记录处理流程如下：
                      

        - 获取远程单条用户记录（远程customer_id为A）；优化数据获取逻辑，避免获取无效数据。

        - 判断用户是否已同步：通过“远程库名+email”查询本地，若已存在则更新数据，通过内存JSON映射数组获取本地已有的customer_id（B）；若不存在则插入数据，生成本地新ID（B）；新增数据查重逻辑，避免重复插入。

        - 若内存JSON映射数组中不存在“当前库名+oc_customer+A”的映射，在临时映射数组中插入该映射关系；新增映射校验。

        - 更新CSV中该远程库oc_customer表的最大ID（取当前处理记录的远程ID A）和同步时间；更新后校验进度。

    4. 同步其他关联表：按表依赖顺序，同步该远程库的其他12张关联表，每个关联表均采用单条记录逐一处理模式，每条关联数据处理逻辑：
                      

        - 查询该远程库中“主键ID > CSV记录最大ID”且关联字段（如customer_id）= 远程ID A的单条关联数据；优化查询逻辑，提升查询效率。

        - 外键转换：通过内存JSON映射数组，找到“远程库名+关联主表名+远程ID A”对应的本地ID B，将关联数据中的远程外键（A）替换为本地ID B；转换后校验关联关系。

        - 插入/更新本地：将处理后的数据插入本地，避免重复数据；插入后校验数据完整性。

        - 若内存JSON映射数组中不存在“当前库名+当前关联表名+远程主键ID”的映射，将该映射关系存入临时映射数组；新增映射去重。

        - 更新CSV：更新该关联表在CSV中的最大ID（取当前处理记录的远程主键ID）和同步时间；更新后校验进度。

        - 重复上述步骤，直至该关联表所有增量关联数据处理完毕。

    5. 连接释放：该远程库所有表、所有单条记录同步完成后，释放当前IP连接，结束该远程库的同步任务；新增连接释放校验，确保连接正常释放，避免资源泄露。

7. 映射持久化与历史备份：所有13个远程库同步任务完成后，将临时映射数组中的新映射批量合并至内存JSON映射数组，一次性覆盖写入id_mapping.json文件（采用临时文件写入方式，避免文件损坏）；同时将临时映射数组中的新映射数据整理为CSV格式，按命名规则保存至历史备份目录，完成本次新映射的历史归档；备份后校验备份文件完整性。

8. 并发任务汇总：生成同步报告（同步库数、表数、总行数、异常数、各库同步耗时、本次新增映射数、IP连接情况），记录同步日志；优化日志内容，增加异常详情，便于问题排查。

9. 任务结束：同步任务正常结束，等待次日自动执行；新增任务结束校验，确保所有数据同步完成、映射与进度文件更新正常。

## 5.2 首次全量同步流程（优化版）

1. 手动触发全量同步（携带初始化参数），忽略CSV文件中已有的最大ID（若有），将所有远程库每张表的最大ID初始化为0；同时清空id_mapping.json文件（若存在），初始化空的临时映射数组；新增全量同步确认机制，避免误触发。

2. 按“整体同步流程”启动13个远程库并发同步，同步时查询远程库中所有数据，采用单条记录逐一处理模式：先同步单条主表记录获得本地ID B，将映射关系存入临时映射数组，再同步该记录的关联数据并通过内存映射绑定B，确保全量同步时每条记录的关联关系精准无误；优化全量同步效率，合理分配线程资源，避免过载。

3. 全量同步完成后，更新CSV文件中所有远程库、每张表的最大ID为对应远程库该表的最大主键ID，更新同步时间；将临时映射数组中的所有映射（全量映射）合并写入id_mapping.json文件，并生成首个CSV历史备份文件，为后续增量同步奠定基础；全量同步完成后，生成全量同步报告，对比远程库与本地库数据量，确保数据完整。

## 5.3 异常处理流程（优化版）

- 远程库连接异常：若某一远程库的db_host、server_ip、server_inner_ip所有可用IP均连接失败（每个IP3秒超时、最多重试3次），且单个数据库单次超时时间达到配置阈值，记录错误日志（含IP连接详情），标记该库同步失败，发送异常通知，不影响其他远程库的同步任务；该库本次未处理的映射数据不写入JSON文件，也不备份至CSV，下次同步重新处理；针对关联网站异常的两个远程库，额外增加连接异常告警，便于优先排查。

- 数据同步异常：单个远程库、单张表的单条记录同步过程中出现错误（如数据格式错误、插入失败），触发事务回滚，撤销该单条记录及其关联数据的同步操作、临时映射数组中的对应映射记录，记录错误日志（含数据详情、错误原因），跳过该单条记录，继续处理下一条记录，不影响其他记录、其他表、其他库的同步；新增异常数据记录，便于后续手动处理。

- CSV操作异常：若CSV进度记录文件损坏、无法读写，自动创建新的CSV文件，初始化表头，基于JSON文件中各远程库每张表的最大远程ID，恢复同步进度，避免同步中断；CSV历史备份文件失败时，仅记录错误日志，不影响同步任务推进，下次同步时重新备份本次新映射；新增CSV文件修复机制，简单损坏可自动修复，无法修复则切换至备份文件。

- IP切换异常：同步过程中IP连接中断，自动切换至备用IP，若备用IP也失败，记录IP异常日志，暂停该库同步，待后续手动重试；该库已处理的映射数据暂存于临时映射数组，重试成功后继续完成同步，失败则不写入JSON和CSV；新增IP异常统计，定期汇总不稳定IP，便于优化IP配置。

- JSON/CSV操作异常：若JSON文件损坏，自动基于最近一次的CSV历史备份文件恢复映射数据；若CSV备份失败，记录错误日志，仅保证JSON文件中的映射数据正常，下次同步时重新备份本次新映射；同步过程中不删除已有的JSON和CSV文件，避免数据丢失；新增文件监控机制，实时监控文件状态，出现异常立即告警。
